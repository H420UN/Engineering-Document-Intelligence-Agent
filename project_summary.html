Problem Being Solved

Engineering consultants spend hours manually searching standards, running calculations, and writing reports. This agent automates the research-to-report workflow using Azure OpenAI as the reasoning engine — letting engineers focus on professional judgement while AI handles information retrieval and synthesis.

Runs engineering calculations (load factors, bearing capacity, carbon)
03
Classifies risks using a 5×5 matrix with required actions
04
Compiles everything into a formal WSP-format engineering report

Interview Talking Points
Q
Why LangGraph over LangChain AgentExecutor? LangGraph gives explicit control over the agent loop — I can add human-in-the-loop approval gates, retry logic, and parallel branches. Critical for production engineering workflows.
Q
How does the agent decide which tool to call? It doesn't — the LLM reasons about what information is needed and outputs structured tool_call JSON. Python executes the function. The LLM never runs code directly.
Q
How would you scale this for WSP? Replace keyword search with Azure AI Search (vector embeddings), containerise on Azure Container Apps, add Managed Identity, and monitor via Application Insights. Same LangGraph graph, production Azure stack.
Q
How do you prevent hallucination? RAG grounds the LLM in retrieved documents. The system prompt mandates citing sources. A production version would add Azure AI Foundry groundedness scoring on all outputs.
